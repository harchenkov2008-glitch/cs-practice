отличия и значения git diff от git show и git log



git log --oneline --stat - показывает историю изменений проекта в сжатом и наглядном виде. (как будто смотрим фото и подпись к нему, без подробностей)



git diff HEAD\~2 HEAD -- lab03\\calc.py - показывает разницу в файле между текущим состоянием и тем, что было два коммита назад. т.е. по сути мы видим наш изначальный первый ввод с суммой



git show HEAD\~1 - показывает подробную информацию одного определенного коммита, в нашем случае история предпоследнего.



git log -S"def" --oneline -- lab03/calc.py - ищет в истории коммитов изменения, которые производились со словом "def" ( оно или появлялось или исчезало) и кратко показывает эти изменения. в нашем случае в командной строке мы видим пустоту, т.к. у нас нет этого слова.



git blame lab03/calc.py - показывает, кто и когда в последний раз менял каждую строчку в файле.



в чем отличия

git diff — показывает разницу между двумя состояниями (например, коммитами). не показывает историю.

git show — показывает один конкретный коммит целиком. все данные о нем и изменения.

git log — показывает историю коммитов, а не содержимое изменений.





Восстановление файла



разница между git restore и git restore --source=HEAD\~2 lab03/calc.py

git restore — это команда, которая «откатывает» изменения, иначе говоря возвращает файлы (или часть файлов) в состояние какого‑то коммита.



git restore --source=HEAD\~2 lab03/calc.py - берёт версию файла, которая была два коммита назад, и ставит её вместо текущей версии в твоей рабочей папке.



В обоих случаях текущие изменения в файле будут потеряны, тк мы их не закоммитили. Git просто заменяет содержимое файла на то, что лежит в коммите, котрый был 2 шага назад





Ошибочный коммит и его отмена

git revert HEAD - создаёт новый коммит, который «отменяет» изменения самого последнего коммита. файлы становятся как до последнего коммита.



git reset --hard - переписывает историю: последний коммит исчезает. файлы как в предыдущем коммите, но «ошибочный» коммит пропадает из истории.



git reset --hard опасен в общих ветках: если ветку уже кто-то скачал, переписывать историю нельзя. git revert безопасен: его можно использовать даже в общих ветках.





Тег рабочей версии

Ветка (branch) — это как рабочая линия (или подвижный указатель), которая движется вперёд. Когда делаешь новый коммит — ветка сама «перепрыгивает» на него



Тег (tag) — это как неподвижная закладка на конкретном коммите. Он никуда не двигается, даже если дальше делаешь новые коммиты.
